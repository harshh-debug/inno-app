# GitHub Copilot Instructions

## Primary Goal
Generate production-ready code with minimal conversation overhead.

## Response Rules
- Return **code only** unless an explanation is explicitly requested.
- Keep responses concise.
- Avoid repeating previous information.
- Prefer modifying existing code over rewriting entire files.
- Ask for clarification only when absolutely necessary.

## Code Style
- Follow the existing project architecture.
- Reuse existing utilities, components, and patterns.
- Avoid introducing unnecessary dependencies.
- Keep functions small and maintainable.
- Write readable code instead of clever code.

## Before Writing Code
- Search the project for existing implementations.
- Prefer extending existing modules over creating new ones.
- Respect current naming conventions.

## Debugging
- Identify the root cause before suggesting fixes.
- Make the smallest possible change.
- Preserve existing behavior unless requested otherwise.

## Performance
- Avoid unnecessary allocations.
- Prefer efficient algorithms.
- Minimize database queries and network requests.

## Security
- Validate all external input.
- Never hardcode secrets.
- Follow secure authentication and authorization practices.

## Token Optimization
- Keep responses brief.
- Do not restate the prompt.
- Do not explain obvious code.
- Summarize only when explicitly asked.

## Context Management
- Treat each request independently when previous context is unavailable.
- Request only the missing information required to complete the task.
